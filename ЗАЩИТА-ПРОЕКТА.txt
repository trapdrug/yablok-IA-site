1. ЧТО ЭТО ЗА ПРОЕКТ
--------------------------------------------------------------------------------
Учебный цифровой двойник склада датчиков air (температура и влажность)
и air plus (плюс CO2-модуль). Программа показывает остатки, бронь, заказы,
поставки в пути, считает риски опозданий, проверяет «а что если поставка
опоздает» и отвечает на вопросы двумя ИИ-помощниками.
Заказчик — Firecode, исполнитель — ЯблокИИ.
Сайт: https://trapdrug.github.io/yablok-IA/ (демо-режим, без сервера).
Полный стенд: сайт http://localhost:5173 + API http://localhost:8000/docs.
Время в программе учебное: 02.11 09:00 МСК (дата компьютера не используется).

2. КАРТА ИНТЕРФЕЙСА
--------------------------------------------------------------------------------
2.1. ВИЗИТКА (первый экран)
  Шапка:
  - Логотип F + FIRECODE, знак ×, логотип-апельсин + ЯблокИИ — связка заказчик × исполнитель.
  - Телефон +7 (499) 130-51-77 — ссылка для звонка.
  Hero-блок:
  - Плашка «Firecode × ЯблокИИ · цифровой двойник».
  - Заголовок «Складской интеллект ЯблокИИ», подпись «На примере датчиков: air и air plus».
  - Кнопка «Открыть приложение ›» — вход в консоль (раздел Склад).
  - Живая карточка справа (цифры с сервера, обновляются сами):
    air (всего / свободно / бронь), air plus (то же),
    «Активные заказы» (и сколько поставок в пути),
    «Возможные риски» (0 — всё в срок, иначе число + подсказка).
  Раздел «Что умеет двойник» — 3 кликабельные карточки-вкладки:
  - «Остатки на складе» → открывает Склад.
  - «ИИ анализ» → открывает проверку задержки.
  - «ИИ консультант» → открывает чат консультанта.
  Блок доверия: «Минцифры России» и «ISO 9001» (данные заказчика).
  Футер: краткое описание, контакты Firecode, копирайт.

2.2. КОНСОЛЬ (7 разделов, меню слева; на телефоне — нижняя панель)
  Верхняя панель (везде одинаковая):
  - «← Главная» — назад на визитку.
  - «онлайн/демо · время» — зелёная точка = живые данные с сервера,
    жёлтая = демо-данные (сервер недоступен).
  - «Обновить» — перечитать данные с сервера.
  - Оранжевая круглая кнопка справа внизу — консультант поверх любой страницы
    (модальное окно, закрывается крестиком/кликом мимо).

  1) СКЛАД. Четыре счётчика (air, air plus, активные заказы, возможные риски),
     список остатков («в наличии / бронь / свободно», полоска % брони),
     список поставок в пути («приедет 03.11 10:00», «опаздывает — вне прогноза»).
     Кнопок действий нет — это витрина цифр.
  2) ЗАКАЗЫ. Фильтры «Товар» и «Состояние», кнопка «+ Новый заказ»
     (форма: клиент, товар, количество, срок → «Создать ›» / «Отмена»),
     галочка «показать закрытые». В каждой строке: поле количества
     (подсказано разумное значение), «Резерв» (забронировать),
     «Отгрузить» (только из брони). Кнопки гаснут, когда действие невозможно.
     Таблица: номер, клиент, товар, шт, бронь, дата готовности, состояние.
  3) ПОСТАВКИ. Кнопка «+ Новая поставка» (поставщик, товар, количество,
     дата — номер присвоится сам: IN-AIR-03, IN-PLUS-02…).
     Счётчик «N в пути · принято: M». У каждой поставки кнопка «Принять ›»:
     товар падает на склад, а поставка ИСЧЕЗАЕТ из списка.
  4) ЗАДЕРЖКА («Расчёт риска… было / стало»). Выбор поставки + новая дата,
     кнопка «Проверить ›» и кнопка-пример «Пример: air → 05.11».
     Результат: таблица «Было», таблица «Стало» (угрозы подсвечены),
     итог со списком заказов с возможными рисками.
     ВАЖНО: расчёт идёт на копии — склад и заказы не меняются.
  5) ИИ-АНАЛИТИК. Строгий помощник: отвечает по-деловому, только по данным.
     4 кнопки-подсказки + своё поле ввода. Под ответом — ссылка
     «на каких данных основан» (раскрывает facts_used) и пометка
     «ответ нейросети / точные данные из программы».
  6) КОНСУЛЬТАНТ. Тот же чат, но объясняет простыми словами и советует,
     что делать. История переписки сохраняется при переходах между вкладками.

3. СТРУКТУРА КОДА
--------------------------------------------------------------------------------
backend/ (Python, FastAPI, SQLite twin.db — сервер создаёт сам из seed):
  app.py    — все HTTP-маршруты (см. п.4) и склейка модулей.
  engine.py — математика двойника (чистые функции, покрыты 15 тестами):
              allocate() — раздача свободного запаса и входящих поставок
              по заказам; readiness — дата готовности каждого заказа;
              scenario_delay() — перенос поставки на копии;
              plan_production() — план партии и диаграмма Ганта.
  store.py  — база SQLite: stock, orders, shipments, компоненты, BOM;
              загрузка эталонов 03/04/05.json; сброс через /api/admin/reset.
  ai.py     — цепочка ответов: 1) чат-модель по ключу (основная),
              2) запасной провайдер, 3) встроенные точные ответы (офлайн).
              Факты для модели ужаты на ~60% (только нужные поля),
              лимит ответа 350 токенов, помнится 3 последние пары реплик.
  models.py — схемы запросов/ответов (включая persona и history для чата).
  Ключи лежат в backend/.env (в git НЕ входит, есть .env.example).

frontend/ (TypeScript + React + Vite):
  App.tsx            — каркас: визитка/консоль, меню 7 разделов, модалка.
  api.ts             — все запросы к API + автопереход в демо-режим без сервера.
  mock.ts            — офлайн-двойник: та же логика, что на сервере.
  pages/Dashboard.tsx  — Склад (витрина).
  pages/Orders.tsx     — заказы, бронь, отгрузка, создание.
  pages/Shipments.tsx  — поставки, приёмка, создание.
  pages/Scenario.tsx   — проверка задержки (было/стало).
  pages/Production.tsx — компоненты и план партии (вкладка «Производство»
                         в меню: детали, план, запуск, график).
  components/AiChat.tsx — чат с историей, персонами analyst/consultant,
                          компактный режим для модалки.
  components/Badges.tsx — плашки состояний («в пути», «возможный риск»…).
  index.css — вся тёмная оранжево-чёрная тема + адаптив
               (ПК — меню слева; планшет/телефон — нижняя панель).

4. ГЛАВНЫЕ ПРАВИЛА-ИНВАРИАНТЫ (сердце защиты — спросят обязательно)
--------------------------------------------------------------------------------
  - Свободно = в наличии минус бронь. Забронировать больше свободного нельзя.
  - Отгрузить можно только из брони (защита от двойных списаний).
  - Принять поставку можно один раз; повтор отклоняется ошибкой.
  - Опоздавшая поставка исключается из прогноза до уточнения даты.
  - Сценарий задержки и план партии считаются НА КОПИИ — база не меняется.
  - Дата готовности заказа = когда хватит свободного + входящих к сроку.
  - ИИ отвечает только по facts_used (ID и цифры из базы, без выдумок);
    неизвестный номер — честное «такой записи нет».

5. API КОНТРАКТ (шпаргалка)
--------------------------------------------------------------------------------
  GET  /api/health, /api/snapshot, /api/orders?status=, /api/shipments
  POST /api/orders {customer,sku,quantity,due_at} — создать заказ (201)
  POST /api/orders/{id}/reserve {qty} — бронь (400 + подсказка, если нельзя)
  POST /api/orders/{id}/ship {qty} — отгрузка (только из брони)
  POST /api/shipments {supplier,sku,quantity,expected_at} — создать (201, номер сам)
  POST /api/shipments/{id}/receive — приёмка (товар на склад, из списка исчезает)
  POST /api/scenarios/delay {shipment_id,new_expected_at} — было/стало + угрозы
  GET  /api/production/status; POST /api/production/plan|start
  POST /api/ai/ask {question,scenario?,persona,history} — {answer,facts_used,via}
  POST /api/admin/reset?fixture=simple|extended; POST /api/admin/now

6. ЭТАЛОНЫ (не меняются, сверяйтесь при демо)
--------------------------------------------------------------------------------
  Простой набор: air 18 (бронь 6, свободно 12), air plus 8 (бронь 5, свободно 3),
  активных заказов 6. Поставки: IN-AIR-01 (air×10 к 03.11 10:00),
  IN-PLUS-01 (plus×6 к 04.11), IN-AIR-02 (air×8 к 05.11).
  Фишка демо: IN-AIR-01 → 05.11 даёт заказы 003 и 005 с возможными рисками.
  Расширенный набор: 36/8/28, 20/8/12, 32 заказа.

7. ДЕМО 3 МИНУТЫ + ВОПРОСЫ ЖЮРИ
--------------------------------------------------------------------------------
  0:30 — Склад: «air 18 (свободно 12), plus 8 (свободно 3)».
  1:00 — Заказы: «ORD-003 ждёт 15 шт, своих 12 не хватает».
  1:30 — Задержка: пресет «Пример: air → 05.11» → 003 и 005 красные.
  2:15 — Консультант: «что будет?» — читаете ответ с номерами и причиной.
  2:45 — Производство/ИИ: «8 plus к 03.11 невозможны — нет CO2, будет 04.11».
  Частые вопросы:
  - «Что будет, если сломается интернет?» — демо-режим со встроенными данными.
  - «Нейросеть не нагаллюцинирует?» — только facts_used + честное «такой записи нет».
  - «Данные не испортятся?» — сценарии на копии, запреты двойных списаний.
  - «Сколько стоит нейросеть?» — ужатые факты (~60% экономии), лимит 350 токенов.
  - «А с телефона?» — адаптив: нижняя панель, кнопки 48px, без бокового скролла.
